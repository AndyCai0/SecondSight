# SecondSight 隐私打码验收矩阵

本矩阵区分三类数据：连续共享给志愿者的打码视频、仅在明显画面变化时发给 DeepSeek
的打码截图、双方转写文本。测试一律使用合成数据，不打开或传播真实邮件、账号、医疗或
财务内容。

## 通过条件

1. 志愿者画面和 DeepSeek 截图都只能看到同一份已经打码的帧。
2. 任何 AX 失败或扫描超时时停止发布新帧，不得用整屏遮罩替代，也不得放行未经检查的新画面。
3. 静态隐私内容不能因为“不是输入框”而漏出；通知不能在一帧中短暂出现。
4. 自动测试通过不等于双屏通过。每项必须记录老人端源画面、志愿者端观察结果和失败后的修复。

## 2026-08-30 双屏合成数据记录

- 老人端主显示器打开合成隐私页面，志愿者端位于另一块显示器并通过真实
  Supabase/LiveKit 会话观察 `screen-redacted`。画面保留页面布局、普通说明和 Continue
  按钮，只对邮箱、账号、BSB、金额、Medicare、生日、诊断、电话、地址、密码、验证码、
  人脸和二维码生成局部黑块。
- 临时诊断采样记录到 AX 17 个矩形、Vision 9 个矩形；输出约 12% 采样像素为黑色，
  单个最大矩形约占显示器 1%，源画面采样为 0%。诊断像素统计随后已从正式代码删除。
- 同一老人屏幕同时可见两个 Safari 窗口时，AX 扫描完成 266 个节点且未超时；旧的
  140ms 预算会在约 280 节点处反复中止，现保留 280ms/1000 节点的有界上限。
- 服务器用纯合成音频签发 AssemblyAI 单次 token，依次收到 partial 和 final，最终转写为
  `This is a synthetic second sight test.` 与 `Please open the settings page.`。没有读取或保存
  用户真实麦克风内容。
- 当前部署的 `ai-referee` 对合法老人会话返回 HTTP 503 `AI features are not enabled`，
  证明阻断点是缺少 `DEEPSEEK_API_KEY`，不是字幕或 LiveKit 通路。密钥补齐后仍需执行本表
  的 DeepSeek 截图节流和风险提醒现场验收。
